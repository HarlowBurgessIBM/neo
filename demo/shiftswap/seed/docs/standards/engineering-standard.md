# VE-IT-STD-007 — Application Engineering Standard: Internal Business Applications

> **Fictional demo content.** Veridane Energy and Port Alder Refinery do not exist. This standard
> was written for the ShiftSwap demonstration.

| | |
| --- | --- |
| Revision | 5 |
| Effective | 2026-04-01 |
| Owner | Marcus Ellery, IT Applications Lead, Port Alder Refinery |
| Applies to | Every internally built business application hosted by Port Alder IT |

## 1. Scope

This standard states what every internal business application must satisfy regardless of what it
does. Requirements specific to one application belong in that application's requirements document.

## 2. Personal data in logs

2.1 Application logs, traces, and metrics shall not contain an employee's name, employee number,
or contact details.

2.2 Where a log entry must refer to a person, it uses an opaque identifier generated by the
application.

2.3 Evidence: every endpoint is exercised with test data, and the captured log output is searched
for the personal values in that test data. Any match is a violation.

## 3. Audit records

3.1 Every business decision that changes state shall write an audit record carrying: the actor,
a UTC timestamp, the action, the outcome, and the revision of the policy or rule set that governed
the decision.

3.2 Audit records are append-only. Application code never updates or deletes one.

3.3 Audit records are not logs. They may identify people, and § 2 does not apply to them. Access
to them is restricted to supervisors and auditors.

## 4. Accessibility

4.1 User interfaces shall conform to WCAG 2.2 Level AA.

4.2 Minimum automated evidence, for every view: zero axe-core violations for the rules tagged
`wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, and `wcag22aa`.

4.3 A manual review with assistive technology is required before site-wide release. It is not
required for a pilot.

## 5. Performance

5.1 Interactive requests shall complete with a 95th-percentile response time of **500 ms or less**,
measured in a staging environment over a 10-minute run at the peak request rate stated in the
application's requirements document.

5.2 An application whose requirements document states no peak request rate is not ready for a
load test.

## 6. Availability

6.1 Tier 3 (business support) applications shall be available for at least **99.5%** of minutes in
each calendar month, measured by the platform synthetic probe against the application's health
endpoint once a minute, excluding announced maintenance windows.

## 7. Supported clients

7.1 Microsoft Edge, current and previous major release (control-room and office desktops).

7.2 Safari on iPadOS, current and previous major release (field tablets).

7.3 Evidence, for each of 7.1 and 7.2: the application's verification steps are completed by hand
on that client.

## 8. Identity

8.1 Applications do not authenticate users. The site access gateway authenticates the user and
forwards two request headers: `X-Employee-Number`, and `X-Roles` (comma-separated; the roles in
use for operations applications are `operator` and `shift-supervisor`).

8.2 Applications authorize on those two values.

8.3 For local development an application may provide a development-only user switcher that sets
the same two headers. It shall be disabled when `NODE_ENV` is `production`.

## 9. Environments

9.1 Port Alder IT hosts Tier 3 applications in production only. A shared staging environment is
planned and is not funded as of this revision.

9.2 Until a staging environment exists, any requirement in this standard whose evidence needs one
cannot be evidenced. It remains a requirement.
